### 1. 外设配置层：告诉 ADC 怎么采

`Core/Src/adc.c` 第 45–61、85–90 行配置了：

22:38

| 配置     | 当前值                          |
| -------- | ------------------------------- |
| 输入引脚 | PA1，即 ADC1 通道 1             |
| 转换方式 | 软件触发、单次转换              |
| 通道数量 | 1 个，不扫描                    |
| 数据格式 | 12 位、右对齐，原始值为 0～4095 |
| 采样时间 | 55.5 个 ADC 时钟周期            |

22:38

`main.c` 中设置 ADC 时钟为 **4 MHz**。加上 12.5 个转换周期，一次硬件转换理论上约需：

t=55.5+12.54×106=17 μst = \frac{55.5+12.5}{4\times10^6} = 17\ \mu st=4×10655.5+12.5=17 μs

这是**一次转换的耗时**，不是你应用每隔多久采一次。

### 2. 驱动层：封装校准和读取

驱动在 `User/Drivers/adc_input.c`。

初始化时，`adc_input_calibrate()` 调用 `HAL_ADCEx_Calibration_Start(&hadc1)`，进行 ADC 自校准，减小内部误差。它不是测量实际参考电压，也不能替代外部电压校准。

每次读取依次调用：

```
HAL_ADC_Start(...);              // 启动一次转换
HAL_ADC_PollForConversion(...);  // 等待转换完成，有超时
HAL_ADC_GetValue(...);           // 取得转换结果
HAL_ADC_Stop(...);               // 停止 ADC
```

这叫**轮询采集**：CPU 启动后等待结果，不是由 DMA 自动搬运，也不是中断通知。

### 3. 应用层：决定何时采、结果怎么用

应用在 `User/App/app_adc.c`。

`app_adc_init()` 首先调用驱动校准。成功后置位 `adc_ready`、记录时间，并输出 `ADC READY`。

主循环不断调用 `app_adc_run()`，但它不会每次都启动 ADC，而是用 `HAL_GetTick()` 判断是否已经过去 **100 ms**。到期后才读取一次，并按下面的公式换算：

```
(raw * 3300 + 2047) / 4095
```

这里假定参考电压为 **3300 mV**，加上 `2047` 是为了整数除法时四舍五入。换算是否准确，也取决于实际参考电压是否接近 3.3 V。

最后输出：

```
ADC raw=... mv=...
```

目前没有平均或滤波，每行就是一次采集结果。正常情况下约 **10 行/秒**。

### 4. main 如何把各层串起来

启动时先调用 `MX_ADC1_Init()` 配置硬件，再调用 `app_adc_init()` 校准。主循环中先执行 `app_imu_run()`，再执行 `app_adc_run()`。

所以 **ADC 的 100 ms 是软件调度周期，不是硬件定时器精确触发**。如果前面的 IMU 读取阻塞，ADC 采集也会延后。
