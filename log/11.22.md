MPU6050 的驱动主线是：**建立 I²C 通信 → 初始化传感器 → 读取原始数据 → 换算物理量 → 按需要计算姿态**。结合你当前工程，可以这样理解。

### 1. 初始化 STM32 的 I²C

先配置 GPIO 和 I²C 外设。你项目使用：

- `PB6` 接 SCL，提供时钟。
- `PB7` 接 SDA，双向传输数据。
- I²C 总线速率为 `100 kHz`。

两根线都是开漏方式，需要上拉电阻。它们空闲时都应为高电平。

### 2. 确认 MPU6050 能通信

MPU6050 的 7 位地址由 AD0 决定：接地为 `0x68`，接高电平为 `0x69`。

使用 STM32 HAL 的 I²C 接口时，设备地址参数通常需要左移一位：

```
#define MPU6050_ADDR (0x68 << 1)
```

然后读取 `WHO_AM_I` 寄存器（`0x75`），MPU6050 正常应返回 `0x68`。注意：这个身份值不随 AD0 改变。

这里能区分两类故障：**读不出来是通信失败；读出来但身份不对，是器件识别失败**。

### 3. 唤醒并配置传感器

MPU6050 上电默认处于睡眠状态，需要通过 `PWR_MGMT_1`（`0x6B`）清除睡眠位，并选择时钟源。

### 4. 一次读取一整帧数据

从 `ACCEL_XOUT_H`（`0x3B`）开始，连续读取 **14 字节**：

```
AX高 AX低 AY高 AY低 AZ高 AZ低
温度高 温度低
GX高 GX低 GY高 GY低 GZ高 GZ低
```

每两个字节组成一个有符号的 16 位数。例如：

```
int16_t ax = (int16_t)(((uint16_t)buf[0] << 8) | buf[1]);
```

高字节在前，转成 `int16_t` 后才能正确表示负方向的加速度或角速度。连续读取比逐个寄存器读更高效，也有利于获得同一次更新的数据。

### 5. 将原始值换算成物理量

换算系数取决于初始化时设置的量程，不能随意套用。例如，**如果**加速度量程为 ±2 g、陀螺仪为 ±250°/s：

```
float ax_g = ax_raw / 16384.0f;
float gx_dps = gx_raw / 131.0f;
float temperature_c = temp_raw / 340.0f + 36.53f;
```

这里的加速度包含重力，因此板子静止时，加速度合量通常约为 `1 g`，不是零。陀螺仪静止时则应接近零，但会有零偏，需要校准。

### 6. 应用层定时读取并输出

你的工程分工是：

- `Core/Src/i2c.c` 配置 STM32 的 I²C 外设。
- `User/Drivers/mpu6050.c` 负责传感器初始化和原始数据读取。
- `User/App/app_imu.c` 负责定时调用、错误重试和串口输出。

当前应用层每 **100 ms** 读取并发送一次，也就是 **10 Hz**；MPU6050 内部的 100 Hz 采样并不等于串口输出频率。

### 7. 通信失败后的恢复

健壮的驱动不能只有正常读取，还要做到：**读写有超时、失败能上报、总线异常能恢复、恢复后重新初始化传感器**。

你目前已经有每秒重试，但缺少 I²C 外设和总线恢复，所以可能出现“插回后一直报错，复位才好”。这属于异常恢复流程不完整，不代表正常的数据读取流程有问题。

最后要区分：**MPU6050 读出的加速度和角速度，不直接等于姿态角**。计算俯仰、横滚等姿态，还需要校准和融合算法；单靠陀螺仪积分会漂移，六轴 MPU6050 的航向角也缺少绝对参考
